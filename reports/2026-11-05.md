## 1. [floci](https://github.com/floci-io/floci)

**一句话用途**　在自己的电脑上模拟常用 AWS 云服务，让开发和测试先用本地数据跑通接口。

![在本地跑通云服务接口](../assets/2026-11-05/floci-io--floci.svg)

**举个例子**　为照片上传功能写测试时，可把测试图片存进本地 S3 模拟存储，检查图片名称、读取结果和删除后的响应，再单独核对真实云环境中的行为。

**适合什么情况**　应用依赖云存储、消息队列或数据库，又想反复测试而不创建真实云资源时，可以先把测试程序指向它的本地接口；也可参考它如何把多种云服务统一成一个开发环境。

**门槛与费用**　门槛中。采用 MIT，可用预编译程序或 Docker 部署；官方容器要求 Docker 23.0+，部分服务的实际执行也依赖 Docker，详见[固定版本安装说明](https://github.com/floci-io/floci/blob/4abccec0c80cb15175a09316a41bb0f16772e881/docs/getting-started/installation.md)。本地模拟本身不产生 AWS 服务账单，机器、存储及另外连接的云资源仍各有成本。

**注意事项**　各服务支持程度不同，部分 AI 接口只返回模拟结果；本地测试通过后，还需在真实云环境核对兼容性与权限。接入时确认测试地址和测试凭据，避免误操作真实资源；需要保留数据时另行配置持久化。

**小范围第一步**　先用虚构图片和一个本地 S3 模拟存储，验证上传、读取、删除三个动作；记下请求和返回结果，再决定是否扩大到队列或数据库。

## 2. [Hyprland](https://github.com/hyprwm/Hyprland)

**一句话用途**　为 Linux 桌面自动排列应用窗口，并按自己的习惯设置工作区、快捷键和动画。

![让应用窗口按规则排好队](../assets/2026-11-05/hyprwm--Hyprland.svg)

**举个例子**　把编辑器和参考文档平铺在同一工作区，把运行日志放到另一个工作区，用快捷键切换；比较这种方式是否更方便定位当前任务。

**适合什么情况**　经常同时查文档、编辑内容和查看终端，希望用键盘切换窗口时，可以研究它的平铺布局、工作区和窗口规则；也适合参考多窗口界面如何减少来回拖拽。

**门槛与费用**　门槛高。采用 BSD-3-Clause，需要适合运行 Wayland 图形会话的 Linux 环境。终端、状态栏、应用启动器等需自行选择和配置；官方主要在 Arch、NixOS 上测试，详见[固定版本安装指南](https://github.com/hyprwm/hyprland-wiki/blob/06365065fb9ebd86bb2e5a3f0bdaa63d7f1b987a/content/getting-started/installation.md)。采用成本主要是设备和配置维护时间。

**注意事项**　它提供搭建桌面的核心工具，应用和系统整合需要自己完成。发行版依赖、显卡、输入法、缩放和屏幕共享应逐项确认；NVIDIA 等环境可能需要额外配置，更新前也要核对组件版本。

**小范围第一步**　先阅读发行版支持与入门指南，在可退出的独立桌面会话里只验证打开终端、平铺窗口和切换工作区三个动作，再检查输入法与显示缩放。

## 3. [ffmpeg-skill](https://github.com/kajisho5/ffmpeg-skill)

**一句话用途**　让 AI 编程助手调用本地 FFmpeg 剪辑音视频，并检查导出文件的时长、编码等属性。

![剪出短片并列清检查项目](../assets/2026-11-05/kajisho5--ffmpeg-skill.svg)

**举个例子**　将自录的产品演示裁成一段短片，配上已校对的字幕，再逐段试看字幕位置、画面裁切和声音同步，保留检查记录后再用于演示。

**适合什么情况**　已有素材，需要裁切、拼接、加字幕或调整画幅时，可参考它把编辑要求转成明确工具调用的方式；也适合研究如何同时记录处理动作、自动检查项与仍需人工判断的部分。

**门槛与费用**　门槛中。采用 MIT，需要 Python 3.10+、FFmpeg 6.1+ 及相应滤镜和字体，字幕等功能对组件有额外要求。素材处理可在本地完成；通过 AI 助手调度时，模型费用和文件可见范围取决于助手方案，额外语音识别还需相应引擎与模型。

**注意事项**　自动检查主要覆盖时长、编码等可测属性，字幕是否易读、画面是否裁对、声音是否自然仍需人工试看。预演命令也不能证明最终文件正确；处理素材前确认助手的数据去向，并保留原始文件。

**小范围第一步**　先选一段自有短片的副本，只做一次裁切并导出新文件；对照时长、画面和声音，查看哪些项目被自动检查、哪些仍需人工确认。

## 4. [project-nomad](https://github.com/Crosstalk-Solutions/project-nomad)

**一句话用途**　把提前下载的百科、课程、地图和可选 AI 问答放进一个本地资料站，供断网时查阅。

![提前备好断网也能查的资料](../assets/2026-11-05/Crosstalk-Solutions--project-nomad.svg)

**举个例子**　外出培训前下载一组公开知识条目和课程，在测试设备断网后检查浏览入口、内容和图片是否仍能打开，再决定需要补齐哪些资料。

**适合什么情况**　需要在网络不稳定的环境保留一套可查的学习资料时，可用它统一管理离线内容；也可以参考它如何组织资料下载、浏览入口、更新和可选的本地问答。

**门槛与费用**　门槛中。主程序采用 Apache-2.0，部署依赖 Debian 系 Linux、Docker 和管理员权限。基础部署建议预留 4GB 内存及 10GB 磁盘，资料和 AI 模型需要额外空间与算力；模型、课程、地图和其他组件的许可应分别核对。

**注意事项**　资料需提前下载，内容是否齐全、是否过期要自行确认。当前主入口没有登录验证，适合受控设备或可信局域网，接入其他网络前需单独设置访问控制；选择远端模型时还要核对上传内容与服务费用。

**小范围第一步**　先列一个小资料包，核对大小和许可；在独立测试设备只启用信息库，以断网后能否打开指定条目作为验收，再考虑加入课程、地图和模型。

## 5. [watermarks-remover](https://github.com/guillaumemeyer/watermarks-remover)

**一句话用途**　检查自有文本的隐形字符和文件的附带属性，并对支持的格式提供清理副本的脚本与接口。

![先检查隐形字符与文件属性](../assets/2026-11-05/guillaumemeyer--watermarks-remover.svg)

**举个例子**　自写活动介绍复制到网页后出现异常空白时，可先定位不可见字符，再在副本中清理，并核对中文、英文和段落换行是否保持原意。

**适合什么情况**　复制文字后出现异常空白，或需要检查文件中附带的来源字段时，可以先查看它的检查报告；集成到上传流程前，应按文件格式确认能检查、能修改和会保留的内容。

**门槛与费用**　门槛中。核心采用 MIT，基础字符检查与脚本清理需要 Python 3.10+，可在本地运行；PDF 等格式可能还需 qpdf 等工具。HTTP 文本清理默认还包含模型改写，需配置后端；模型与外部后端的费用、许可和数据去向须另外核对。

**注意事项**　检查结果不能证明文字由谁创作，也不能保证所有水印消失；部分隐形字符对语言和排版有作用。应保留原件与必要的来源说明，逐项核对清理差异，避免把来源清理当成内容真实性证明。

**小范围第一步**　先用虚构短文副本，通过独立字符脚本只做检查，人工确认每个异常项；再仅在副本上清理，比较文字、空格与换行是否符合预期。
